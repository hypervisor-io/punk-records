One brain, many agents

Like a brain maps memory to areas, Punk Records partitions memory into regions. A group of agents registers to a region and coordinates through its shared, append-only record.

regionsMemory maps to regions

A region is a namespace of append-only, bi-temporal facts with typed links, observations, mental models and an entity graph. Agents register to one and see each other's writes. The antenna is MCP.

claim_workMany writers, no conflicts

Concurrent writers never overwrite, identical writes collapse by content hash, and work-claim leases stop two agents chasing the same sub-key. Same repo, no clash. A guarantee, not a convention.

branch / mergeFork, experiment, merge back

Fork a region to a git branch, work offline, merge conclusions back. Merge is replay plus dedup, so it cannot conflict. Read the region as of any past instant.

The memory engine

Not a vector store with a REST hat. An append-only, bi-temporal fact store whose scoring pipeline explains itself: every hit carries score_components, the evidence for why it surfaced.

Retrieval

Scored recallscore_components

Hybrid FTS + vector fusion with bounded salience boosts. Every hit shows its evidence.

Bridge discoverylink

A fact linked to two search hits surfaces even when it never matches the query text.

Token-budget recallmax_tokens

Fill a context budget with ranked facts instead of an arbitrary top-k.

Time travelrecall_as_of

Read the region as of any instant. "Errors last month" parses to a real time window.

Query expansionexpand

One flag rewrites the query into variants and fuses their results, rerank preserved.

Triplet retrievaltriplet_search

Ranks source, edge and target together: the relation itself must match the query.

Reflectreflect

Evidence gathered in tiers, answers cite what was actually retrieved. Fabricated provenance cannot survive.

Trust & scale

Observationsproof_count

Consolidation folds raw facts into beliefs carrying their sources. Stale beliefs get flagged.

Secret scrubbingdefense: block

Keys, DSNs and JWTs redacted or blocked at every write path. The raw secret never lands.

Contradiction watchcontradicts

An LLM judge sweeps for fact pairs that disagree and links them, on a hard invocation budget.

Feedback loopfeedback

Rated recalls reweight what they surfaced; re-remembering a fact reinforces it.

Entity graphmemory.entities

Named entities extracted per fact, fuzzy aliases merged: a knowledge graph over the region. Opt-in.

Vectors that scaleivf_nprobe

int8 quantization, 4x smaller, plus an in-memory IVF index for sublinear search. Both opt-in, pure Go.

Benchmark in the binarypunk membench

recall@k and MRR against a JSONL dataset, deterministic, in CI. Regressions fail a command, not a vibe check.

The taxonomy

Memory is not one undifferentiated pile. Facts sit in tiers that outrank each other on recall, and the edges between them are a closed vocabulary the store validates on write.

Tiers, by key prefix

Recall prefers the higher tier and drops the evidence it already cites, so a belief answers instead of the twelve raw facts behind it.

Tier 1/mental-models/

Curated syntheses you write. Outrank everything and are never superseded by a machine pass. The layer reflect reads first.

Tier 2/observations/

Beliefs consolidation folded out of raw facts, carrying source_ids and proof_count. Flagged stale when newer evidence lands.

Tier 3your own keys

Raw facts, the evidence layer. /code-map/ lives here too: an architecture map seeded from an existing repo, delta-updated so a deleted package stops being injected.

Aside/entities/

Extracted entities and their co-occurrence graph. Never injected inline; surfaced separately as a known-entities line.

Ephemeral/agent-sessions/

Raw hook capture: prompts, tool calls, answers. 30-day TTL, and deliberately excluded from injected context. It is feedstock for consolidation, not the thing your next session reads.

Edges, all 14 of them

A link outside this set is rejected at write time, so the semantics stay queryable. Every edge carries a weight and an optional sentence, and that sentence is embedded too: the relation itself is retrievable, not just its endpoints.

Why the graph earns its keep

invalidated_by demotes the superseded fact on every read. Edge count drives bridge discovery: a fact linked to two or more search hits surfaces even when it matches your query textually not at all, which is how the reasoning behind two decisions gets found without anyone tagging it.

Why it holds together

Works with no model

Registration, claims, dedup, retrieval, budgets and the audit ledger all run with AI disabled. A model is invited for judgment only, and never sits on the critical path.

The log is the truth

Every write, claim, route, refusal and finding is an append-only event with provenance: who, when, which task. Replay any run. Attribute every token.

Bring your own everything

Any OpenAI-compatible endpoint, cloud or local Ollama. Any MCP tool server. Secrets named only by environment variable. Nothing leaves your network unless a tool does.

Your agents, with a memory

Punk Records doubles as persistent memory for the agents you already run. Hooks capture what they do - six coding agents (Claude Code, Cursor, OpenCode, pi, Antigravity, Copilot CLI) plus the general assistants Hermes and OpenClaw; the next session starts already knowing the project.

terminal
# run the memory server
punk serve                    # :9090

# wire Claude Code to it, once per machine
punk connect claude-code      # SessionStart / UserPromptSubmit
                              # PostToolUse / Stop hooks

# or wire up any other supported agent
punk connect cursor | opencode | pi | antigravity | copilot | hermes | openclaw

# mine recurring investigations into skill drafts
punk skills propose --min-count 3
                              # writes proposed-skills/<slug>/SKILL.md

Capture

Prompts, tool calls and answers land as facts under /agent-sessions/ in a per-project namespace: replay-deduped, secret-scrubbed, embedded and entity-extracted by the async enricher.

Inject

The next SessionStart receives a token-budgeted context block: known entities first, then important and recent facts.

Consolidate

Sessions fold into durable observations over time. Raw capture expires after 30 days; knowledge stays.

Share

Point every host's PUNK_URL at one server and machines share a project's memory. Capture is fail-open: a dead server never breaks a session.

Rinnegan: the other half

Hook capture is forward-looking. It learns what happens after you wire it up, so a repository with ten years of history starts empty. Rinnegan reads the code that is already there, deterministically, and punk turns it into memory.

day one on an existing repo
# index the tree, then seed punk from the architecture map
rinnegan index
rinnegan map --json | punk seed rinnegan

# one fact per domain, in the namespace your agent reads
seeded agent-myrepo: 14 written, 0 unchanged, 0 removed

# re-run on every commit: unchanged domains cost nothing
rinnegan map --json | punk seed rinnegan
seeded agent-myrepo: 1 written, 13 unchanged, 0 removed

A domain that no longer exists is tombstoned, so a deleted package stops being injected as though it were still there. Facts you wrote by hand under the same prefix are never touched.

  • Two halves, one seam. Rinnegan answers what the code is, right now, from the AST. Punk answers what happened and why: the decision, the dead end, the incident. Neither is recoverable from the other.
  • Deterministic, no model. Same corpus gives a byte-identical index. Semantic discovery is classical LSA (TF-IDF plus truncated SVD), not embeddings, so nothing leaves the machine and nothing drifts between runs.
  • Provenance on every edge. Each fact is tagged ast_exact through unresolved, and only ast_exact is ground truth. Same contract punk holds itself to with score_components: no confident claim without its evidence.
  • Both speak MCP. Run them side by side and the agent gets understand and lookup for the code alongside recall and remember for the history. rinnegan install <agent> prints its own config; punk has punk connect.
  • One rule. Do not copy the symbol graph into punk. Punk is append-only, so an indexed copy of your code rots silently. Rinnegan re-derives it in a moment. Store only what it can never recover.
the loop, with both wired
punk recall            # why is it this way, what did we already try
rinnegan understand    # what the code actually is, provenance-tagged
      ... write the patch ...
rinnegan verify        # does the patch hold against the graph
punk remember          # what we learned, for the next session

Connect your agent

Punk Records speaks MCP over streamable HTTP (/mcp, bearer-authed) and stdio (punk mcp). Any MCP client connects with a few lines. Mint a token with punk apikey create --name my-agent.

terminal, streamable HTTP
# register the brain once; it is then available in every session
claude mcp add punk-records \
  --transport http https://brain.internal/mcp \
  --header "Authorization: Bearer $PUNK_TOKEN"
edit ~/.cursor/mcp.json, native HTTP
{
  "mcpServers": {
    "punk-records": {
      "url": "https://brain.internal/mcp",
      "headers": { "Authorization": "Bearer $PUNK_TOKEN" }
    }
  }
}
edit ~/.codeium/windsurf/mcp_config.json, via mcp-remote
{
  "mcpServers": {
    "punk-records": {
      "command": "npx",
      "args": ["-y", "mcp-remote",
               "https://brain.internal/mcp",
               "--header", "Authorization: Bearer ${PUNK_TOKEN}"]
    }
  }
}
edit .vscode/mcp.json, Copilot agent mode
{
  "servers": {
    "punk-records": {
      "type": "http",
      "url": "https://brain.internal/mcp",
      "headers": { "Authorization": "Bearer ${input:amk}" }
    }
  }
}
edit claude_desktop_config.json, via mcp-remote
{
  "mcpServers": {
    "punk-records": {
      "command": "npx",

any MCP client, co-located: stdio, no network

      "command": "punk-records",

Once connected, the agent gets one toolbelt for the whole brain: register, claim_work / release_work, remember / remember_document / remember_model, recall / search (hybrid, scored, temporal, token-budgeted, expanded) / unified_search / triplet_search / recall_as_of, reflect, feedback, profile / diagnose, link / unlink / neighbors, and submit_task / get_task. Task and region changes stream back over MCP subscriptions.

What a session looks like

two agents, one region
// two agents on the same repo region, no conflict
register      { region: "repo-main", agent: "refactorer" }
claim_work    { region: "repo-main", key: "/file/api.go" }   // mine
// a second agent claiming /file/api.go is refused; it takes /file/db.go

remember      { key: "/finding/pool-leak",
                body: "leak after 14:02 deploy" }
link          { from: "/finding/pool-leak",
                to: "/file/api.go", type: "caused_by" }

search        { query: "connection pool", hybrid: true }
recall_as_of  { prefix: "/finding",
                as_of: "2026-07-06T12:00:00Z" }

release_work  { region: "repo-main", key: "/file/api.go" }
  • Register a group of agents to one region; they share its memory and see each other's writes.
  • Claim a sub-key before touching it; a live claim by anyone else is refused, so work never overlaps.
  • Append facts with full provenance; identical concurrent writes collapse to one.
  • Link facts into a graph: a change touches a file, a finding is caused by a change.
  • Search full-text or hybrid with explained scores and token budgets; recall as of any past instant.
  • Branch the region to git, experiment, and merge back conflict-free.

Deploy in a minute

from zero to serving
# one line: downloads the latest release, verifies its checksum,
# installs the binary, and runs first-time migrations
curl -fsSL https://hypervisor-io.github.io/punk-records/install | bash -s -- --init
punk serve                   # API + /mcp on :9090, dispatcher, hot-reload

# or do it by hand: binary, source, or container
tar xzf punk_*_linux_amd64.tar.gz && ./punk --version
go install github.com/hypervisor-io/punk-records/cmd/punk@latest
docker compose up            # or: docker build -t punk .
punk migrate up              # SQLite by default, zero external services
punk validate specs          # the shipped database pack must pass

# mint an agent token, prove the brain with no model at all
punk apikey create --name my-agent
make demo                    # signed webhook, routed, audited (no model)

# enable a model when ready (any OpenAI-compatible endpoint)
cp punk.example.yaml config.yaml   # set ai.enabled: true + one profile

# run on Postgres instead of SQLite: same schema, pure-Go driver
docker run -d -p 5432:5432 -e POSTGRES_USER=punk \
  -e POSTGRES_PASSWORD=secret -e POSTGRES_DB=punk postgres:16
# config.yaml:  db: { driver: postgres,
#   dsn: postgres://punk:secret@localhost:5432/punk?sslmode=disable }
punk migrate up  --config config.yaml
punk serve       --config config.yaml    # memory, regions, MCP: identical
  • Single binary. No database server to run; SQLite by default. Point it at Postgres for scale: same schema, same tests.
  • Backup is trivial. punk backup snapshots SQLite; regions export to JSONL; specs live in git.
  • Bearer-keyed. Open until the first key exists, then every request needs one. Keys carry an optional identity claim for Okta/Entra agent registries.
  • Observable. OpenTelemetry spans for every agent, tool call and route, exported OTLP. An operator console ships at /ui.
  • Sovereign. Self-hosted, BYO model (Ollama included), secrets by env var. Nothing leaves your network unless a tool server does.

Also in the record

Bi-temporal memory

Append-only with tombstones, provenance and validity windows. Per-prefix write ACLs, per-fact expiry, recency boosts.

Evals

Every task freezes its tool-call world. Re-run under new specs with punk replay, score the trajectory: a private eval suite no public benchmark can contaminate.

Cost

Every model call rated locally into a burn table. Per-agent daily budgets, a hot-reloadable kill switch, burn-rate alerts.

Governance

An autonomy ladder gates every tool call. Agents propose actions into an approval gate; telemetry is fenced as untrusted input.
